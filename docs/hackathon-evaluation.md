## Метрики и пределы

- **Precision@5**: доля размеченных релевантных событий среди пяти верхних уникальных fingerprints по профилю; затем среднее по профилям. Неполная пятёрка не улучшает показатель искусственно: знаменатель 5.
- **Валидность оснований**: существование ссылок/признаков и точное вхождение цитаты в сохранённый источник. В live-v2 — 100%. Это не проверка экономической причинности.
- **Банковская атрибуция**: автоматический контроль типа/даты/страницы/качества использованной цитаты; формальных нарушений 0. Семантическую ложную атрибуцию должен отдельно разметить эксперт.
- **Дедупликация**: нормализованные точные дубли; качество объединения разных пересказов не измерено.
- **Расходы**: input/output usage, сохранённые квитанции и неизвестные исходы. Без тарифа `costRub=null`, gateway units не пересчитываются в ₽.
- **Задержка**: live-v2 median ≈23,6 с, p95 ≈44,0 с на случай; включает очередь/граф/сетевые вызовы. Это локальный снимок, не SLA. Demo latency не включает сеть/LLM.

В согласованном плане цели — references 100%, false bank attribution 0 и P@5≥0,80. Численный P@5 достигнут на регрессии. Независимая смысловая groundedness/полезность рекомендаций, качество живого извлечения как отдельная экспертная метрика и реальная устойчивость по новым отраслевым новостям не подтверждены.

## Экспертный протокол перед финальным тегом

1. Заморозить SHA, модели, алгоритм, версии корпуса и настройки.
2. Подготовить новый, ранее не просмотренный набор событий и разметку с участием банковского/предметного эксперта; зафиксировать критерии до запуска.
3. Проверить не только цитату, но и связь события с компанией, правильное понимание признаков, актуальность банковского тезиса, гипотезы и проверяемость действий.
4. Отдельно отметить случаи без позиции банка/с конфликтами/с OCR-числами; не засчитывать молчаливое исключение как смысловой успех.
5. Опубликовать фактические показатели, ошибки, стоимость/её неизвестность, latency и ограничения. Не менять labels ради порога.

## Регулярный процесс сопровождения

| Когда                                | Что проверять                                                                             | Действие                                                          |
| ------------------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| После ручного исследования           | Ошибки/partial, провалы источников, неизвестные резервы, usage                            | Технический разбор по runId/trace                                 |
| Еженедельно, вручную                 | Нерелевантность, wrong_evidence/wrong_bank, пропущенные важные события, устаревший корпус | Эксперт отмечает verdict/status/expertNote в «Экспертном разборе» |
| После смены модели/корпуса/алгоритма | Development + контрфактические пары и замороженная регрессия                              | Сравнить с baseline, сохранить новую ревизию и отчёт              |
| Перед выпуском                       | Новый независимый набор, доступы, бюджет/отказы, интеграции                               | Зафиксировать экспертное заключение и SHA                         |

Профессиональная роль и интересы учитываются отдельно от grants. Обратная связь не обучает модель автоматически и не запускает платное исследование по расписанию. [Команды явных live-прогонов](hackathon-acceptance.md#reproduce).
